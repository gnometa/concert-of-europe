# Event pacing audit, 1821-1836

Generated by `scripts/audit_pacing.py` (read-only; base MTTH only, MTTH
modifiers are ignored, so rates are upper bounds). "Available" counts
self-firing `country_event`s with a MTTH whose trigger admits the tag
(explicit `tag =`, directly or inside `OR`) or that carry no tag test but are
year-gated into the window.

## Read this first

- Nothing in the tree fails the >25% miss test: the lowest window/MTTH ratio
  is 3.6, so every year-gated event has time to fire. No suggested MTTH
  changes are needed on that axis.
- The per-tag rate is dominated by a handful of unbounded repeatable events;
  strip those out and every tag sits at roughly 1-3 events per year.
- Most sub-monthly MTTH events listed further down are self-limiting through
  a map/state change (annexation, colonisation, war end) rather than a flag,
  which is why the automatic guard check cannot see it. Check by hand before
  changing any of them (99986 and 99800 were the two genuine repeaters and
  are now flag-guarded; see "Fixed" at the end).

## Fixed (2026-09-06)

- **99986** `00_CoE_RoI.txt` (GRE/EPI liberation, MTTH 1 mo, no guard) - added
  `NOT = { has_country_flag = independence_chaos_liberation }` to the trigger and
  the matching `set_country_flag` to the option, so it fires at most once per
  country instead of monthly for the whole war.
- **99800** `POLflavor.txt` (Krakow, MTTH 1 day) - added a
  `krakow_integrated` country flag guard (two tags can pass the trigger, so a
  flag rather than `fire_only_once`).
- **1001401** `RUSTurkishWarGVG.txt` - already guarded by
  `adrianople_offer_made` (set in both options, negated in the trigger); no
  double fire possible. Its follow-ups were staggered: 1001402 (GP reaction)
  now `days = 7`, 1001403 (TUR mirror) now `days = 3`.
- **1000900** `ZollvereinGVG.txt` - 1000901/1000902 moved from `days = 2` to
  `days = 30` / `days = 60`. Both are `is_triggered_only` notifications with no
  expiring gate, so the delay is safe.
- **1001601** `ASHWarGVG.txt` - 1001603 (Ashanti mirror) moved from an
  immediate `country_event = 1001603` to `days = 5`. Also dropped the redundant
  `exists = yes` after `tag = ENG` in 1001600's trigger.
- **36996** `ENGFlavor.txt` (Norfolk Island, MTTH 3 mo from 1825) - the option
  always secedes province 2508, so the `2508 = { empty = yes }` trigger
  self-negates; added `fire_only_once = yes` to make that explicit and stop the
  audit counting it as ~4 events/year for ENG.

### Checked, no change needed

- **ACW2 block (95260-95283, USA)** - none of these are year-gated. 95260
  requires `has_global_flag = american_civil_war_has_happened`; every secession
  event (95265-95281) requires REB control of its convention province or the
  `sons_of_liberty` province modifier plus a state-level militancy/ideology
  test, and negates its own `<TAG>_created` flag. 95282/95283 (Alaska, Hawaii)
  require the USA to own province 3 / 658 while having *lost* core states.
  None can fire in 1830-1833 in a normal game; the audit lists them only
  because it cannot see state-based gating.
- **FRA majors (10400, 10401, 10402, 10410, 96055, 99921, 99922, 99926,
  99927)** - all state- or flag-gated, and 10400, 10410, 99921, 99922, 99926,
  99927 additionally carry `fire_only_once = yes`. 10401/10402 both need
  `has_country_flag = 2nd_republic` and negate each other's outcome flags. No
  unguarded duplicates.
- **CB grant next to `war = {}`** (ASHWarGVG 1001600, RUSTurkishWarGVG 1001400)
  - left in place. Vanilla uses exactly this pairing
  (`events/CivilizationAndGunBoats.txt` lines ~1342 and ~1501: a
  `casus_belli = { ... cut_down_to_size months = 12 }` grant immediately
  followed by `war = { attacker_goal = { casus_belli = cut_down_to_size } }`),
  so it is the engine-attested idiom rather than a bug, even though it does
  leave a second live CB for 12 months.

- **decisions/RUS.txt:182** (`the_port_of_novorossiysk`) tested
  `has_global_flag = treaty_of_adrianople`, the *decision's* name rather than
  the flag its effect sets. Corrected to `has_global_flag = adrianople_treaty`,
  which is what `treaty_of_adrianople`'s effect and event 1001401 both set, so
  the port decision now disappears once the treaty is signed.
