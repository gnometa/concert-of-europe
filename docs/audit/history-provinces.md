## Fixed (2026-09-06)

- **Duplicate history files for one id (was 4, now 0).** Kept the copy in the folder where the
  rest of the province's `map/region.txt` region lives; `git rm`ed the other.
  - 1396 Api, 1397 Sandakan — region `BRU_1394` (1393/1394/1395 all in `asia/`) → kept
    `history/provinces/asia/`, deleted the `indonesia/` copies. Files were byte-identical.
  - 2539 Bougainville — region `AST_2534` (2534 Solomon Islands, 2536 Santa Cruz Islands both in
    `pacific island/`) → kept `pacific island/`, deleted the `indonesia/` copy. Byte-identical.
  - 686 Line Islands — region `HAW_658` (658/2524/2526 in `pacific island/`) → kept
    `pacific island/`, deleted the `indonesia/` copy. The two differed: `indonesia/` had
    `terrain = jungle`, `pacific island/` has `terrain = insular`. `insular` is correct for a
    coral-atoll group and matches its region neighbours Wake (2524) and Palmyra (2526).
  - Note (out of scope, not fixed): `map/region.txt` defines both `BRU_1394` and `BRU_1396`, and
    both list provinces 1396 and 1397.
- **Dated block before the start date (was 1, now 0).** `history/provinces/japan/1661 - Nagasaki.txt`
  had `1821.1.1 = { naval_base = 1 }`. `docs/wiki/province-history-modding.md` documents dated
  blocks only as "so that they do not appear until later bookmarks" — it does **not** state that a
  block dated before the active bookmark is replayed at start. Rather than rely on unverified
  engine behaviour, the `naval_base = 1` was merged into the top-level block and the dated block
  removed; the result at 1821.9.1 is the same either way.
